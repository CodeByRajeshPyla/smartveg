## 1. Why chips

A real shop has 50+ vegetables. From `01_PROJECT_CONTEXT.md`:
- **Top** — the 6-8 items that sell every day; ~80% of transactions. **Shown first by default.**
- **Regular** — sell most days.
- **Slow** — seasonal or occasional.
- **Piece / Bunch** — sold per piece or bunch, no weighing.

The vendor finds Tomato instantly instead of scrolling.

---

## 2. The same `setState` loop again

```
tap "Slow"
 -> ChoiceChip's onSelected runs
 -> setState(() { _filter = 'slow'; })
 -> Flutter marks the screen dirty -> calls build()
 -> build asks _visibleProducts -> where keeps only category == 'slow' -> [Beans]
 -> GridView: itemCount = 1 -> itemBuilder builds one tile -> Beans
 -> the "Slow" chip is drawn selected (because _filter == 'slow')
```
**One variable, `_filter`, controls both** the grid and which chip looks selected.

---

## 3. The code (`lib/weigh_screen.dart`)

### State — which chip is selected
```dart
String _filter = 'top';     // starts on Top, as the design says
```

### The chip names — a Map
```dart
static const Map<String, String> _chips = {
  'top': 'Top (80%)',        // key (used in code) : label (shown on screen)
  'regular': 'Regular',
  'piece': 'Piece / Bunch',
  'slow': 'Slow',
  'all': 'All',
};
```

### The filter — `where`
```dart
List<Product> get _visibleProducts {
  return products.where((p) {
    if (_filter == 'all') return true;            // keep everything
    if (_filter == 'piece') return !p.isWeighed;  // keep pc/bun items
    return p.category == _filter;                 // keep matching category
  }).toList();
}
```

### The chip row
```dart
SingleChildScrollView(
  scrollDirection: Axis.horizontal,
  padding: const EdgeInsets.fromLTRB(16, 0, 16, 12),
  child: Row(
    children: [
      for (final chip in _chips.entries)
        Padding(
          padding: const EdgeInsets.only(right: 8),
          child: ChoiceChip(
            label: Text(chip.value),
            selected: _filter == chip.key,
            onSelected: (_) {
              setState(() {
                _filter = chip.key;
              });
            },
            showCheckmark: false,
            selectedColor: const Color(0xFF0F766E),
            labelStyle: TextStyle(
              fontWeight: FontWeight.w600,
              color: _filter == chip.key ? Colors.white : const Color(0xFF0F172A),
            ),
          ),
        ),
    ],
  ),
),
```

### The grid uses the filtered list
```dart
itemCount: _visibleProducts.length,
itemBuilder: (context, index) {
  return _tile(_visibleProducts[index]);
},
```

## 4. `where` — the filter

> **`where` asks a yes/no question about each item and keeps only the yes ones.**

```dart
[3, 8, 12, 5].where((n) => n > 4)      ->  [8, 12, 5]
```

With Slow selected:
| Product | `category == 'slow'`? | |
|---|---|---|
| Tomato | 'top' — no | dropped |
| Potato | 'top' — no | dropped |
| ... | ... | ... |
| Beans | 'slow' — **yes** | **kept** |

Real life: the teacher says "students with more than 35 marks, stand up" — everyone is
asked the same question; only those who match stand up.

`.toList()` — `where` gives a lazy result (worked out only when used); `toList()` turns
it into a real `List` the grid can count and index.

### Why Coriander shows under both Top and Piece / Bunch
Its data: `category: 'top'`, `unit: 'bun'`. The **Top** chip checks the **category**;
the **Piece / Bunch** chip checks the **unit**. Two different questions — Coriander says
yes to both.

## 5. DART CONCEPTS USED HERE

| Feature | Syntax | Meaning |
|---|---|---|
| **Map** | `{'top': 'Top (80%)', ...}` | pairs of **key -> value**. `map['top']` -> `'Top (80%)'` |
| `.entries` | `for (final chip in _chips.entries)` | loop over pairs: `chip.key` = `'top'`, `chip.value` = `'Top (80%)'` |
| **collection `for`** | `children: [ for (x in list) Widget(...) ]` | a `for` **inside a list literal** — one widget per item, no `{ }` |
| **`where`** | `list.where((p) => test)` | keeps only items where the test is true |
| `.toList()` | `.where(...).toList()` | lazy result -> real List |
| `!` (not) | `!p.isWeighed` | flips true <-> false |
| `static const` | `static const Map _chips` | one shared constant for the class |
| ignored parameter `_` | `onSelected: (_) { ... }` | Flutter passes a value not needed here |
| getter with a body | `List<Product> get _visibleProducts { return ...; }` | recalculated every time `build` asks for it |

## New widgets
| Widget | Meaning |
|---|---|
| `ChoiceChip(label, selected, onSelected)` | pill-shaped option; one is chosen |
| `SingleChildScrollView(scrollDirection: Axis.horizontal)` | lets the chip row scroll sideways if wider than the screen |
| `EdgeInsets.fromLTRB(16, 0, 16, 12)` | padding Left, Top, Right, Bottom |

## 6. Thinking — learning in the AI era (asked during this lesson)

**Partly true:** memorising syntax is wasted effort; typing repetitive code is slow (hence
fast lessons); AI writes code faster.

**Where "AI writes it, I don't need to understand it" broke in this project:**
- the first Tare button zeroed only the phone — caught by looking at the real LCD
- "Scanning..." forever — caught by reading `Bluetooth must be turned on` in the log
- the sketch had no WRITE property — found by reading the sketch

AI cannot see the LCD, the shopkeeper, or the ESP32.

**Often there is no AI:** viva and interviews, company code that cannot be pasted into
AI, no internet at the stall, plan limits, niche hardware problems.
**Test: "If this broke at 9 pm at the stall with no AI, could I fix it?"**

**Three levels of understanding:**
| Level | Meaning | Needed for |
|---|---|---|
| 1. Read and explain | "this line connects and waits until done" | every line in the project |
| 2. Change and debug | modify it, fix it when it breaks | the core: BLE, streams, stability, billing, DB |
| 3. Write from scratch | blank file, no help | fundamentals: widgets, state, setState, async, lists |

**Depth before breadth:** one project finished end to end beats five half-done
tutorials; fundamentals transfer to the next technology, syntax does not.

> **AI makes typing cheap. It makes understanding more valuable — that is what separates
> you from everyone else using the same AI.**
