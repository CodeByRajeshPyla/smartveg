## 1. The two widgets

### `Scaffold` — the standard page skeleton
Provides a background colour, default text styling, and named slots:
`appBar`, `body`, `floatingActionButton`, `bottomNavigationBar`.

`body` is used constantly; the others come later (bottom nav in F2.11).
The splash has **no AppBar** — it is a full-screen moment, not a navigable page.

This is what fixed the red-text-and-yellow-underline from F1.1.

### `Column` — stacks children vertically
In the order listed. Its sibling **`Row`** does the same horizontally. Between them
they are most of Flutter layout.

---

## 2. `child:` vs `children:` — the most common beginner error

| Parameter | Takes | Used by |
|---|---|---|
| `child:` | **one** widget | `Center`, `Scaffold.body`, `Container`, `Padding` |
| `children:` | a **list** — square brackets `[ ]` | `Column`, `Row`, `ListView` |

**The parameter name tells you which.** Mixing them up is the classic first error.

## 3. The layout code

```dart
return MaterialApp(
  title: 'SmartVeg',
  home: Scaffold(
    body: Center(
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Container( ... ),          // green kg logo
          const SizedBox(height: 24),
          const Text('SmartVeg', ...),
          const SizedBox(height: 8),
          const Text('IoT weighing & billing', ...),
        ],
      ),
    ),
  ),
);
```

**The indentation IS the tree diagram.**

### `mainAxisAlignment: MainAxisAlignment.center`
A Column's **main axis is vertical**, so this centres the children *within the Column*.

**Why is it needed when `Center` is already there?**
`Center` positions **the Column**; the Column decides how **its own children** sit
inside it. Two different jobs, two different widgets.

(`crossAxisAlignment` is the other axis — horizontal for a Column.)

## 4. `Container` and `BoxDecoration`

```dart
Container(
  width: 120,
  height: 120,
  decoration: BoxDecoration(
    color: const Color(0xFF0F766E),
    borderRadius: BorderRadius.circular(28),
  ),
  child: const Center(
    child: Text('kg', style: TextStyle(
      fontSize: 56, fontWeight: FontWeight.bold, color: Colors.white)),
  ),
),
```

`Container` = the general-purpose box: size it, colour it, pad it, round it, one
`child` inside.

### The trap
> **Container has BOTH a `color:` property AND a `decoration:` property, and you
> cannot use both at once — Flutter throws an error.**

The moment rounded corners, borders or shadows are needed, the colour must move
**inside** `BoxDecoration`.

### `Center` inside the Container
The box is 120x120 but `kg` is small. Without centring it lands top-left **inside the
box**. Same rule as F1.1, one level down:
> **Position is never automatic, at any level of the tree.**

## 5. Colour format — ARGB, not RGB

```dart
Color(0xFF0F766E)
```
| Part | Meaning |
|---|---|
| `0x` | this is a hex number |
| `FF` | **opacity** — `FF` fully opaque, `00` invisible |
| `0F 76 6E` | red, green, blue |

> **Alpha comes FIRST.** Forgetting it gives an invisible widget.

### Project colours (from `projectfiles/DESIGN.md`)
| Hex | Role |
|---|---|
| `#0F766E` | **Primary** brand green (teal). DESIGN.md: "the single source of truth for the brand green" |
| `#0F172A` | **Neutral / carbon ink** — all heavy typography |
| `#64748B` | mid grey — subtitle |

**Why not `Colors.black`?** Pure black is harsh on a white screen. Design systems
almost always use a very dark slate instead.

## 6. `SizedBox` — spacing

```dart
const SizedBox(height: 24),
```
An empty box of fixed size. Nothing is drawn — pure spacing. The normal way to space
children in a Column.

| Widget | Use |
|---|---|
| `SizedBox` | gaps **between** siblings |
| `Padding` | space **around** a single widget |

## 7. How layout actually resolves (the prediction)

**Q: The Column is centred. You add a 120px box above the two Texts. Does the text move?**

**A: Yes — the whole group re-centres, so the texts shift down** (roughly 60px).
`Center` centres the Column **as a whole**, not each child individually.

> **A parent lays out its children, then sizes itself to fit them, then its own parent
> positions that result. Layout flows down the tree; sizes flow back up.**

## 9. Git — a new status code

```
 M lib/main.dart                 modified
 D test/widget_test.dart         DELETED  <- new
?? web/                          untracked
```

**`D` = deleted.** Git tracked the file and it is now gone. A deletion is a change like
any other: `git add .` stages it, and the commit records
`delete mode 100644 test/widget_test.dart` — the counterpart to `create mode`.
Because it is recorded, the file can be restored from history later.

`web/` and the `.metadata` change appeared when Flutter added web support to the
project. Those are real project source (`index.html`, a manifest), not build output, so
they belong in Git.

## 11. Viva answers

**Q: What does Scaffold do?**
Provides the standard page structure — background, default text styling, and slots for
an app bar, body, floating action button and bottom navigation.

**Q: Column vs Row?**
Column stacks children vertically, Row horizontally.

**Q: `child` vs `children`?**
`child` takes a single widget; `children` takes a list. The parameter name says which
the widget accepts.

**Q: Why does Container have both `color` and `decoration`?**
`color` is a shorthand for a plain fill. Anything more — rounded corners, borders,
shadows — requires `BoxDecoration`, and the two cannot be used together.

**Q: What does `Color(0xFF0F766E)` mean?**
An ARGB hex colour: `FF` opacity followed by the red, green and blue components.
