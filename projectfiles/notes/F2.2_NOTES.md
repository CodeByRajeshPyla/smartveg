Course: 03_FLUTTER_COURSE.md · Screen 04 (Weigh & Select) · Stage 2 · **STATUS: GATE PASSED**

---

## 1. The problem async solves

Bluetooth takes **time**. Scanning takes seconds; connecting takes a moment. If Dart
stopped everything while waiting, the whole app would **freeze** — the progress bar would
stop, taps would do nothing.

Dart's answer: start the slow job, **keep the app running**, and pick up again when the
job is finished.

---

## 2. DART CONCEPTS USED HERE

| Feature | Syntax | Meaning |
|---|---|---|
| **Future** | `Future<void>` | a value that arrives **later** — "I will finish in the future" |
| `Future<T>` | `Future<int>`, `Future<void>` | `T` = what you get when it finishes. `void` = nothing, only a "done" signal |
| **async** | `Future<void> f() async { ... }` | marks a function that is allowed to use `await`. An async function always returns a `Future` |
| **await** | `await something();` | **pause this function** until `something` finishes, then continue to the next line |
| `Future.delayed` | `await Future.delayed(const Duration(seconds: 5));` | a Future that just finishes after a given time — a pause |
| `final` | `final device = ...;` | assigned once, never reassigned. Type is inferred |
| `list.first` | `list.first` | the first item. **Throws (crashes) if the list is empty** |
| `list.isEmpty` | `if (list.isEmpty)` | `true` when the list has no items. Opposite: `isNotEmpty` |
| **early return / guard** | `if (bad) { return; }` | leave the function now; nothing below runs. Guards the code below from bad data |
| **named argument** | `connect(license: License.nonprofit)` | passed by name, not position |
| comment | `// code` | Dart skips the line — useful to switch a line off for an experiment |

### `await` pauses only the FUNCTION, never the APP
While `_scan()` waits at an `await`, the Timer keeps ticking, `setState` keeps running,
the progress bar keeps filling. Only the lines **below the `await` in this function** wait.

### Proved by experiment — removing `await`
```
WITH await                          WITHOUT await
found 1 device(s)                   found 1 device(s)
onMethodCall: connect               connected!            <- printed first: a LIE
...GATT_SUCCESS                     onMethodCall: connect
connected!       <- after, true     ...GATT_SUCCESS
```
> **Without `await` there is no crash — Dart starts the job and immediately runs the next
> line. The code below runs before the job is done.** Worse than a crash: it fails
> silently later (e.g. reading weight from a scale not yet connected).

## 3. BLE words

| Word | Meaning |
|---|---|
| **advertising** | the ESP32 broadcasts its name (`ESP32-Scale`) over and over, several times a second, so phones can find it |
| **scanning** | the phone **listens** for advertisements. It only *hears*; nothing is sent back |
| **connect** | a two-way private link between the phone and one device. Once connected, the ESP32 **stops advertising** |
| **address** | `30:76:F5:E5:80:46` — the device's unique hardware ID |
| **GATT** | the rules connected BLE devices use to exchange data (used in F2.3 to read the weight) |
| **MTU** | largest message size; negotiated to 512 bytes — plenty for `"1486.0,1"` |
| `GATT_SUCCESS (0)` | status 0 = success; any other number is an error code |
| `LINK_SUPERVISION_TIMEOUT` | the other device went silent (e.g. ESP32 reset) and the phone gave up on the link |

**BLE devices are not paired in Android Settings.** The app connects directly. Pairing
from Settings gives "Can't communicate with ESP32-Scale" — if it is listed there, Forget it.

## 4. The code

```dart
import 'package:flutter_blue_plus/flutter_blue_plus.dart';

// in initState():
_scan();

Future<void> _scan() async {
  await FlutterBluePlus.startScan(
    withNames: ['ESP32-Scale'],                 // only report devices with this name
    timeout: const Duration(seconds: 5),        // stop listening after 5 s
  );
  await Future.delayed(const Duration(seconds: 5));   // let the phone listen
  print('found ${FlutterBluePlus.lastScanResults.length} device(s)');
  if (FlutterBluePlus.lastScanResults.isEmpty) {      // guard
    print('scale not found');
    return;
  }

  final device = FlutterBluePlus.lastScanResults.first.device;
  await device.connect(license: License.nonprofit);
  print('connected!');
}
```

- `_scan()` is a **separate method**, called from `initState` — `initState` itself cannot
  be `async`.
- `License.nonprofit` — flutter_blue_plus is free for personal/educational use;
  commercial use needs a paid licence.

### Why wait 5 seconds before reading `lastScanResults`
```
second 0    startScan()  -> listening starts, list EMPTY
second 0.1  ESP32 advertises -> phone hears it -> list: [ESP32-Scale]
second 5    timeout -> read list -> found 1 device(s)
```
> **A scan is not instant. Results arrive over time while the phone listens.** Read the
> list at second 0 and it is empty, even with the ESP32 right beside the phone.

### Why the guard before `.first`
The list is empty when:
- phone Bluetooth is **off**
- the ESP32 is **unplugged** or has no power
- the ESP32 is **out of range** (~10 m indoors)
- another phone (e.g. nRF Connect) is **already connected** — the ESP32 stops advertising

Tested **on purpose** with the ESP32 unplugged: `found 0 device(s)` -> `scale not found`
-> no crash. **Test the failure case deliberately, not only the happy one.**

## 7. GATE — PASSED

**Q: What does `await` do; what if it is missing?** It pauses the function until the job
finishes. Without it Dart moves straight to the next line — `connected!` printed before
connecting had even started.

**Q: What is `Future<void>`?** A function that takes time and gives back nothing — only a
signal that it finished. That signal is what `await` waits for.

**Q: Why wait 5 seconds?** The scan needs time to hear the ESP32's advertisements; read
immediately and the list is empty.

**Q: Why check `isEmpty` before `.first`?** `.first` crashes on an empty list — e.g. when
the ESP32 is off or out of range.

**Q: What are `0.0` and `1`?** Weight in grams and the stable flag. The app does not show
them yet because it is not listening.

## 8. `_scan()` in simple English, line by line

```dart
Future<void> _scan() async {
  await FlutterBluePlus.startScan(
      withNames: ['ESP32-Scale'], timeout: const Duration(seconds: 5));
  await Future.delayed(const Duration(seconds: 5));
  if (FlutterBluePlus.lastScanResults.isEmpty) { return; }
  final device = FlutterBluePlus.lastScanResults.first.device;
  await device.connect(license: License.nonprofit);
}
```

| Line | In plain English |
|---|---|
| `Future<void> _scan() async {` | "A job called `_scan`. It takes time (`async`) and gives back nothing, only *done* (`Future<void>`)." |
| `await FlutterBluePlus.startScan(...)` | "Phone, start listening. Only tell me about `ESP32-Scale`. Stop after 5 seconds." |
| `await Future.delayed(...)` | "Wait 5 seconds, so the phone has time to hear the ESP32." |
| `if (...isEmpty) { return; }` | "If nobody was heard, give up and stop here." Protects against a crash. |
| `final device = ...first.device;` | "Take the first device heard and call it `device`." |
| `await device.connect(...)` | "Connect to it, and wait until the connection is complete." |

**One sentence:** listen 5 seconds for ESP32-Scale; if nothing was heard, stop; otherwise
connect and wait until connected.

**Real life:** walk into a crowded room, listen 5 seconds for someone calling
"ESP32-Scale!". Nobody called -> leave. Someone did -> walk over and shake hands (connect).

## 9. Which words are fixed, and which are mine?

The words come from four places. **Only group 4 is mine** — everything else must be
spelled exactly.

### 1. Dart keywords — built into the language (cannot be used as names)
| Keyword | Meaning |
|---|---|
| `void` | nothing — gives back no value |
| `async` | this function takes time and may use `await` |
| `await` | wait here until this job finishes, then go to the next line |
| `if` | check a condition; run the code inside only if true |
| `return` | leave the function now |
| `final` | set once, never changed |
| `const` | fixed at compile time; Dart can reuse it |

### 2. Dart built-in classes and members — come with Dart, no import
| Name | Meaning |
|---|---|
| `Future` | a value that arrives later |
| `Future.delayed(...)` | a Future that just finishes after a time — a pause |
| `Duration` | a length of time |
| `seconds:` | named parameter of Duration (also `milliseconds:`, `minutes:`) |
| `.isEmpty` | true if a list has no items |
| `.first` | the first item of a list (crashes if empty) |

### 3. From the `flutter_blue_plus` package — exist only because of the import
| Name | Meaning |
|---|---|
| `FlutterBluePlus` | the main class — remote control for the phone's Bluetooth |
| `.startScan(...)` | start listening for nearby devices |
| `withNames:` | filter — only these names |
| `timeout:` | stop scanning after this time |
| `.lastScanResults` | the list of devices found |
| `.device` | the device inside one scan result |
| `.connect(...)` | connect to the device |
| `license:` / `License.nonprofit` | the free licence for personal/educational use |

### 4. Names I chose — could be anything
| Name | Could also be |
|---|---|
| `_scan` | `_findScale`, `_startBluetooth` |
| `device` (after `final`) | `scale`, `myEsp` |

**`device` appears twice with two different origins:**
```dart
final device = FlutterBluePlus.lastScanResults.first.device;
//    ^^^^^^ MY variable name                         ^^^^^^ PACKAGE's property (fixed)
```

**No Flutter words at all** in this function — no widgets, no `setState`. It is pure
Dart + the Bluetooth package. Flutter only matters for drawing the screen.

**Telling them apart in VS Code:** **hover** a word to see its description; **Ctrl+Click**
to jump to where it is defined (Ctrl+Click `startScan` opens the package's source).

## 10. How do you know to write code like this?

Nobody memorises it — professionals neither. Three steps:

### Step 1 — plan in plain English, no code
```
1. listen for the scale for a while
2. wait so the phone has time to hear it
3. if nothing was found, stop
4. take the device that was found
5. connect to it
```
If you cannot say it in English, you cannot write it in code.

### Step 2 — find the tool for each step in the package's documentation
Every package has a **README** with examples. On this computer:
```
C:\Users\rajeshpyla\AppData\Local\Pub\Cache\hosted\pub.dev\flutter_blue_plus-2.3.14\README.md
```
Online: **pub.dev/packages/flutter_blue_plus**

| Plan step | README section | Their example |
|---|---|---|
| listen for the scale | "Scan for devices" | `await FlutterBluePlus.startScan(withNames:["Bluno"], timeout: Duration(seconds:15));` |
| the list of found devices | API table | `lastScanResults` — the most recent scan results |
| connect | "Connect to a device" | `await device.connect();` |
| what the device offers (F2.3) | "Discover services" | `await device.discoverServices();` |

We only **adapted their example**: `"Bluno"` -> `'ESP32-Scale'`, 15 s -> 5 s.

### Step 3 — glue with Dart
| Plan says | Dart glue |
|---|---|
| wait until done | `await` |
| wait some time | `Future.delayed(...)` |
| if nothing found, stop | `if (...) { return; }` |
| take the first | `.first` |
| remember it | `final device = ...` |

> **English plan -> package docs for each step -> Dart to glue them.**

**Everyday helpers:** autocomplete (type `FlutterBluePlus.` and VS Code lists everything),
hover, Ctrl+Click, and error messages.

**Viva answer to "how did you write this?":** "I planned the steps, read the
flutter_blue_plus documentation and examples, and adapted them to my scale."
