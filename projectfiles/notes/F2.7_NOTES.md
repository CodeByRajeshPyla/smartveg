# F2.7 — Stability gate: tiles disabled while settling

Course: 03_FLUTTER_COURSE.md · Screen 04b (Weigh & Select — SETTLING) · Stage 2 ·
**DEEP LESSON** · **STATUS: GATE PASSED**

Gate as met: press the load cell -> badge SETTLING, amber banner appears, tiles fade and
cannot be tapped; let go -> STABLE, banner gone, tiles light up and tapping shows
"Tomato selected".

---

## 1. Why — a non-negotiable project rule

> **Weight must be stable before billing.** (`01_PROJECT_CONTEXT.md`)

The vendor drops tomatoes in the basket; the reading swings `1.342 -> 1.410 -> 1.388`. A
tap now would capture a weight that is still moving -> **wrong price on the bill**. So
while settling, tiles must be:
1. **visibly disabled** — the vendor *sees* they must wait
2. **untappable** — tapping does nothing even if they try

Safety rules from the spec:
- "Add to bill" requires weight **stable AND > 10 g** (the > 10 g part comes in F2.8)
- tiles are **visibly disabled/greyed** while settling

---

## 2. One variable, four effects

When the load cell is pressed, **four things change** — all from **`_isStable`**:

| # | Change | Code |
|---|---|---|
| 1 | badge turns amber **SETTLING** | `WeightBar(isStable: _isStable)` -> ternary colour/text |
| 2 | amber **banner** appears | `if (!_isStable) Container(...)` |
| 3 | tiles **fade** | `Opacity(opacity: _isStable ? 1.0 : 0.35)` |
| 4 | tiles **untappable** | `onTap: _isStable ? () {...} : null` |

```
ESP32 sends "503.0,0" -> _isStable = false -> setState -> build -> all four update together
```

## 3. Built in three visible pieces

### Piece 1 — fade (Opacity)
```dart
return Opacity(
  opacity: _isStable ? 1.0 : 0.35,
  child: _tile(_visibleProducts[index]),
);
```
`Opacity` makes any widget see-through: 1.0 solid, 0.0 invisible.
**Opacity only changes the LOOK — a faded widget can still be tapped.**

### Piece 2 — untappable (GestureDetector + `onTap: null`)
```dart
final p = _visibleProducts[index];
return GestureDetector(
  onTap: _isStable
      ? () {
          ScaffoldMessenger.of(context).showSnackBar(
            SnackBar(content: Text('${p.name} selected')),
          );
        }
      : null,
  child: Opacity(
    opacity: _isStable ? 1.0 : 0.35,
    child: _tile(p),
  ),
);
```
> **Flutter rule: `onTap: null` (or `onPressed: null`) = disabled.** That is how every
> Flutter button and gesture is switched off.

- `GestureDetector(onTap:, child:)` — detects taps on any widget
- `SnackBar` — short message sliding up from the bottom; here only to *see* the tap work.
  In F2.8 the tap adds the item to the bill.
- `ScaffoldMessenger.of(context).showSnackBar(...)` — "find this screen's message area and
  show this"
- `final p = ...` — name the product once, use it twice

Tested both: stable -> "Tomato selected"; settling -> nothing.

### Piece 3 — the banner (collection `if`)
```dart
if (!_isStable)
  Container(
    margin: const EdgeInsets.fromLTRB(16, 0, 16, 12),
    padding: const EdgeInsets.all(12),
    decoration: BoxDecoration(
      color: const Color(0xFFFEF3C7),
      border: Border.all(color: const Color(0xFFD97706)),
      borderRadius: BorderRadius.circular(12),
    ),
    child: const Row(
      children: [
        Icon(Icons.lock_outline, color: Color(0xFFD97706)),
        SizedBox(width: 8),
        Expanded(
          child: Text('Wait for STABLE before selecting a vegetable'),
        ),
      ],
    ),
  ),
```
- amber `#D97706` = DESIGN.md colour for unstable weight; `#FEF3C7` light amber background
- `Icons.lock_outline` — Flutter has thousands of built-in icons named `Icons.something`
- `Expanded` around the text lets it wrap to two lines instead of overflowing

## 4. Ternary vs collection `if` — HIDDEN vs REMOVED

| | Ternary `? :` | Collection `if` |
|---|---|---|
| chooses | **a value** | **whether a widget exists** |
| when false | widget still there, other value | widget **gone**, takes no space |
| use for | colour, opacity, text, onTap | show/hide a whole widget |

```dart
opacity: _isStable ? 1.0 : 0.35,         // tile ALWAYS in the tree; only a value changes
if (!_isStable) Container(...banner...)  // when stable the banner is NOT IN THE LIST
```

**Seen on the phone:** when the banner appears, the **chips move down**; when it goes,
the **chips move back up**. If the banner were only invisible (opacity 0), the chips
would stay put with an empty gap. **The chips moving proves it is removed, not hidden.**

---

## 5. Why the tiles are faded at startup

```dart
bool _isStable = false;      // starting value
```
Before the scale connects (~6 s), no reading has arrived, so `_isStable` is still
`false` -> tiles faded. **Correct: no scale = no weight = no billing.** Safe by default.

---

## 6. Observation — weight still moves 1-5 g while STABLE

The ESP32's rule (`isStable()` in the sketch): **last 5 readings within 5 g**. So
"stable" means "moving less than 5 g", not "frozen". The wobble is sensor noise; the load
cell is accurate to **±3 g**. Money effect: 3 g of tomatoes at ₹45/kg ~ 13 paise.

Real shop scales handle it by:
1. showing weight in **2 g or 5 g steps** (the *scale division*)
2. a **stable lock** — hold the value while stable until it changes by > 5 g
   (DESIGN.md "Stable Lock")
3. averaging more readings on the ESP32 (`get_units(10)`) — smoother, slower

Not a blocker: in F2.8 the weight is **captured at the moment of the tap**, so the bill
gets one fixed number. Stable lock -> polish list.

## 7. DART / FLUTTER CONCEPTS USED HERE

| Feature | Syntax | Meaning |
|---|---|---|
| ternary giving a function or null | `onTap: ok ? () {...} : null` | enabled or disabled |
| collection `if` | `[ if (cond) Widget() ]` | widget in the list only when true |
| `!` (not) | `!_isStable` | settling |
| `margin` vs `padding` | `margin:` / `padding:` | margin = space **outside** the box; padding = space **inside** |
| `Opacity` | `Opacity(opacity: 0.35, child:)` | see-through; look only |
| `GestureDetector` | `GestureDetector(onTap:, child:)` | tap detection on any widget |
| `SnackBar` | `ScaffoldMessenger.of(context).showSnackBar(SnackBar(content: ...))` | temporary bottom message |
| `Icon` | `Icon(Icons.lock_outline, color: ...)` | built-in icon |

## 8. GATE — PASSED

**Q: Why disable tiles while settling?** The weight is still changing, so a tap would
capture the wrong weight and the price on the bill would be wrong.

**Q: What makes a tile untappable?** `onTap: null`. Opacity only changes the look.

**Q: What does `if (!_isStable)` do to the banner?** Removes it from the widget list when
stable — the chips move up into its space, proving it is gone, not hidden.

**Q: Four effects of pressing the load cell, one cause?** Badge amber, banner shown,
tiles faded, tiles untappable — all from `_isStable`.

**Q: Why faded at startup?** `_isStable` starts `false` and no reading has arrived yet —
correct: no scale, no billing.
