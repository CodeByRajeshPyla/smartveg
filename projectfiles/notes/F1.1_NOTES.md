# F1.1 — Widgets and the Widget Tree

## 1. The one idea

> **Everything on screen is a widget.** Widgets nest inside other widgets, forming a
> **tree**.

Not "most things" — *everything*. The green square, the text, the padding around it,
the centring, the progress bar, the screen itself: all widgets.

This differs from Android/web, where there is a layout file **plus** styles **plus**
code. In Flutter there is **one kind of thing**, composed by nesting. Colour, padding,
alignment, spacing — all widgets wrapping other widgets.

**Tree** = a hierarchy in parent-child order, like folders inside folders — not a pile
of widgets side by side.

---

## 2. The splash screen as a tree

```
MaterialApp                    <- the app itself
 └─ Scaffold                   <- the screen (white background)
     └─ Center                 <- puts its child in the middle
         └─ Column             <- stacks children vertically
             ├─ Container      <- the green square
             │   └─ Text("kg")
             ├─ Text("SmartVeg")
             ├─ Text("IoT weighing & billing")
             └─ Container      <- the grey box
                 └─ Column
                     ├─ Text("Scanning for ESP32-Scale...")
                     ├─ LinearProgressIndicator
                     └─ Text("Tip: keep phone within 10m...")
```

**The code IS the tree.** Dart's nesting matches the diagram line for line — which is
why Flutter code is deeply indented and why the closing `)))` pile up at the bottom.
That is not bad style; it is the tree structure showing through.

---

## 3. Why each widget does only one job

`Center` only centres. `Column` only stacks. `Text` only draws text.

**Why not one mega-widget?** It would need dozens of parameters and you would fight it
constantly. Instead: small pieces, combined. Centred column -> wrap `Column` in
`Center`. Needs padding too -> wrap that in `Padding`.

> **You compose behaviour by nesting, instead of configuring one big thing.**

That principle is why the trees get deep.

---

## 4. Properties vs widgets

Colour is a **property** of Container (`color:`), not a separate widget.

But Flutter often gives **both** routes: there is a `Padding` **widget** and also a
`padding:` **property** on Container. Same result, two ways. Both appear in real code.

## 5. The code

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const SmartvegApp());
}

class SmartvegApp extends StatelessWidget {
  const SmartvegApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(home: Text("SmartVeg"));
  }
}
```

| Line | What it does |
|---|---|
| `import 'package:flutter/material.dart';` | brings in Material Design — `MaterialApp`, `Scaffold`, `Text`, `Column`, `Container`. Without it none of those names exist. **Every Flutter file starts with it.** |
| `void main()` | where Dart starts, as in any Dart program |
| `runApp(...)` | Flutter's: takes **one widget**, makes it the root of the tree, paints it. Everything else hangs off that single widget. |
| `extends StatelessWidget` | how you make your own widget. "Stateless" = never changes after being drawn (F1.3). |
| `super.key` | Flutter bookkeeping; ignore for now |
| `Widget build(BuildContext context)` | **the most important method in Flutter.** Returns a widget tree — it *describes* what this widget looks like. Flutter calls it when it needs to draw. **You never call it yourself.** |

## 6. What the ugly first result taught

Result on the phone: **red text with a yellow underline, jammed in the top-left.**

Tree at that moment:
```
MaterialApp
 └─ Text("SmartVeg")
```

**Two separate problems, two separate causes:**

1. **Red text + yellow underline = deliberate.** Flutter's signal for *"this text has
   no styling context"*. Not an error, not a crash — the framework makes unstyled text
   look obviously wrong so it cannot be shipped by accident.
   `MaterialApp` sets up the app (theming, navigation, fonts) but **does not paint a
   page** — no background, no default text colour. **`Scaffold` provides that.**

2. **Top-left = nothing positions it.** `Text` draws text; it does not centre itself.
   `MaterialApp` does not centre its child.
   > **Position in Flutter is never automatic — some widget in the tree must be
   > responsible for it.** That is exactly why `Center` exists as its own widget.

Both missing widgets are added in F1.2.

## 7. `title:` vs `android:label` — where the app's name really comes from

`title: 'SmartVeg'` in MaterialApp is **not visual**. It describes the app to the
**operating system**: the Android recent-apps switcher, the browser tab on web, and
screen readers. Nothing in the widget tree draws it.

On modern Android it often does nothing at all, because the real name comes from:

```xml
android:label="SmartVeg"
```
in `android/app/src/main/AndroidManifest.xml` — that is what shows under the app icon.
(It said `vegbill` by default.)

| Where | Controls |
|---|---|
| `android:label` (AndroidManifest.xml) | the name under the icon and in the task switcher |
| `title:` (MaterialApp) | a description for the OS; largely redundant on Android, used on web |

**Changing the manifest needs a full rebuild** — not hot reload, not hot restart. It is
Android config, read when the app is *installed*, not when it runs. Press `q`, then
`flutter run` again.

> Three levels of change: **`r`** reload (Dart UI code) · **`R`** restart (`main()`,
> packages, startup code) · **full rebuild** (native/Android config).

## 8. Problems hit

**`error - The name 'MyApp' isn't a class - test\widget_test.dart`**
`flutter create` generated a test for the counter app that referenced `MyApp`. Deleting
the counter app left the test pointing at a class that no longer exists. The app itself
was fine — the stale test was the compile error. Deleted `test/widget_test.dart`.
*A compile error anywhere blocks hot reload everywhere.*

**Hot reload "not working"** — the real cause: `flutter run` was **not running**. The
prompt read `PS D:\vegbill>`, so PowerShell took `r` as a command and looked for a
program called `r`.
> **`r` is a single keypress sent to the running `flutter run` process — not a command
> typed with Enter.** It only works while the app is running and that terminal has
> focus.
Leave `flutter run` going for the whole session; open a **second terminal** for Git
commands instead of killing the app.
